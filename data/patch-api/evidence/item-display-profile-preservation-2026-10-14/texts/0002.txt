# Item cooldown selector falsification

Date: 2026-10-14. Read-only narrow review. No canonical edits, workloads, builds/checks, hashes, service actions, or delegation. Requested `docs/wiki/index.md` read; prior working-tree changes were left untouched.

## Finding

**Reject the `C_Item.GetItemCooldown({bagID=0, slotIndex=8})` test input as established `ItemInfo` evidence.** Both cached Retail and PTR `ItemDocumentation.lua` declare one required, nonnil `itemInfo: ItemInfo`, returning `(number, number, bool)`; the declaration does not enumerate ItemInfo representations. `ItemLocation` is a separately named type in other declarations, sometimes explicitly with `Mixin = "ItemLocationMixin"`. Its existence and the simulator's location helpers do not establish that a location table is accepted by this ItemInfo parameter. Do not assert native rejection either: the declaration leaves concrete runtime validation unspecified.

ItemInfo prose in the same cached Retail/PTR generated docs describes **Item ID, Link, or Name** (e.g. ItemUpgradeDocumentation.lua; Retail HousingCatalogUIDocumentation.lua additionally says ItemID, name, or link). The strongest directly grounded usable `C_Item.GetItemCooldown` test candidates are therefore numeric item ID, item link, and name. Numeric ID/link are additionally supported by the actual simulator parser below. Name is declaration prose, but is not currently supported by the shared parser and should not be presented as a simulator-parsable test until code establishes it. No type alias definition enumerating a universal ItemInfo union was found; keep claims tied to these explicit per-API docs.

## Simulator parser facts

`src/c_api/item_spell/c_item.rs::parse_item_id_from_val` accepts positive numeric Lua values and strings parsed as an `item` hyperlink/prefix or decimal numeric text. Other values, including tables, return `None`. `C_Item.GetItemIDForItemInfo` calls exactly this parser, so it is a useful concrete parser behavior check for ID and link, but is not by itself a native ItemInfo specification.

Separate `location_item` handles tables with `equipmentSlotIndex`, or bag tables with `bagID`/`slotIndex` (missing bag/slot numerically default to zero); it consults simulator equipped/bag state. Other APIs use this helper. The fixture's proposed `{ bagID=0, slotIndex=8 }` thus has a known simulator location interpretation, but that does not make it a supported `ItemInfo` selector. For a narrow test of the proposed ItemInfo-to-ID path, prefer `6948` and a concrete item link whose embedded ID is 6948. If testing the location helper, keep it under an API whose selector is actually ItemLocation/ItemLocationMixin, not as proof for GetItemCooldown.

## Fixture integration defects

- `fixture.rs` uses `crate::support::env()`. In `tests/c_item_api.rs`, support is declared as `mod support`, and the child test modules import `use crate::support::env;`; this test's path is valid when the body is appended to either existing child module. `support::env` is `pub(crate)` and returns `WowLuaEnv`. No fixture crate-path defect found.
- The fixture calls `C_Container.GetItemCooldown(12345)` but current `c_container.rs` registers that stub; it is distinct from `GetContainerItemCooldown(bag, slot)`. Its declaration permits zero returns. This is not a missing-container namespace issue.
- Missing bag-slot is asserted, but the fixture does **not** assert absent `C_Container.GetItemCooldown(itemID)`; it only asserts missing `C_Item.GetItemCooldown(999999)`. Thus the report's stated missing-item C_Container policy/test coverage is absent. Add a separate assertion only if that simulator policy remains in the intended scope; do not imply native semantics.
- Fixture lacks explicit `use wow_ui_sim::lua_api::WowLuaEnv`—not needed, since it does not name the type. Its `env` import is sufficient.

## Concrete recommendation

Use ID and item-link inputs for C_Item coverage; optionally separately test a name only after establishing current simulator parsing/lookup. Remove the bag `ItemLocation` table case from the ItemInfo acceptance claim (or relabel it as an explicitly unverified hypothesis, not a passing required contract). Keep bag/slot behavior on `C_Container.GetContainerItemCooldown(0, 8)`. Add the omitted C_Container absent-item assertion only if verifying the explicitly chosen simulator missing-record policy. No claim about native behavior for undeclared concrete selectors.
