## Exact source scopes and updates

- `src/loader/mod.rs`, `LoadTiming`: `xml_frame_create_time` is documented “Time creating/configuring frames from XML.” `xml_frame_setup_time` and `xml_frame_finalize_time` are explicitly documented as subsets of `xml_frame_create_time`; leaf fields likewise identify setup/finalize subsets. `total()` sums `independently_counted_time()` only: `io + xml_parse + xml_process + lua_exec + saved_vars`. The frame fields are not added to total. `accumulate()` adds frame fields independently as reporting counters.
- `src/loader/xml_file.rs::process_timed_frame`: starts a timer around all of `process_frame_element(...)`, then adds its elapsed duration to `xml_frame_create_time`. This includes frame preparation, setup, and finalization. It is reached inside `process_element_with_exclusive_timing` for a top-level frame element.
- `src/loader/xml_frame.rs::create_frame_from_xml`: prepares a non-virtual frame, calls `build_and_setup_frame`, resolves its ID, then calls `finalize_frame`. Thus the outer XML frame timer encloses both setup and finalize for a successfully created frame. Virtual/intrinsic early registration and preparation failures return before these phases; the enclosing `process_timed_frame` still measures the dispatch call if it returns successfully.
- `src/loader/xml_frame/setup.rs::setup_frame`: `xml_frame_setup_time` starts before CreateFrame Lua execution and ends after parent registration and XML/intrinsic property application. `frame_exec_lua_time` and `frame_apply_props_time` are nested measured portions. `src/loader/xml_frame.rs::build_and_setup_frame` measures Lua-string building separately as `frame_code_build_time`, before `setup_frame`; that duration is outside `xml_frame_setup_time` but inside the outer create timer.
- `src/loader/xml_frame/finalize.rs::finalize_frame`: `xml_frame_finalize_time` wraps `create_children_and_finalize`. This work creates layer children, recursively creates child frames, applies animations and button/bar extras, repairs parent keys, resolves named anchors, and fires lifecycle scripts. The finalize timer therefore includes nested child-frame creation/finalization. `frame_layer_children_time`, `frame_anim_time`, `frame_button_time`, and `frame_lifecycle_time` are subset/detail scopes; child-frame timers accrue separately into shared `LoadTiming` during the parent finalize interval.
- `src/loader/xml_file.rs::process_element_with_exclusive_timing`: `xml_process_time` is different: it measures each top-level element and subtracts the delta in `independently_counted_time()` (I/O, XML parse, Lua exec, SavedVariables). It does not subtract any XML/frame diagnostic counters. Nested XML processing can therefore have its own process timing while the caller's process timer also spans nested work; the explicit subtraction only covers the independently-counted buckets.

## Finding

**Accepted, with main qualification:** Per-call finalization is enclosed by a top-level frame operation, but aggregate counters do not share matching invocation sets. `process_timed_frame` adds creation time around XML element dispatch; recursive child creation calls `create_frame_from_xml` directly inside parent finalization and accrues additional finalize scopes. Thus a 'subset' comment is not an aggregate subset invariant; do not claim those aggregate field labels alone are precise enough for exclusive-cost interpretation. Finalize is a broad inclusive recursive scope, while setup is the earlier initial-creation phase. Child frame create/finalize measurements accrue while the parent finalize timer is running. Consequently summing these fields double-counts overlapping time, and an aggregate finalize sum may exceed aggregate create or XML-process sums without violating a documented invariant. The report's `2750970854 ns` finalize, `2207029055 ns` create, and `2224790049 ns` process figures alone do not demonstrate an accumulator bug.

**Rejected:** “Every label is an exclusive bucket” and “each finalize timer must be ≤ its matching create timer” are unsupported interpretations. The source explicitly marks subset/detail fields and shows recursive nesting. No in-scope counter bug is established by the supplied aggregates.
