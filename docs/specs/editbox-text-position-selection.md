# EditBox text position and selection

Shared EditBox cursor and highlighted-range methods expose bounded text-position behavior. This spec covers valid UTF-8 byte boundaries, selected-range `Insert`, and changed programmatic text replacement, not the entire input system.

## What it must do

- [x] `SetCursorPosition` accepts valid UTF-8 byte offsets; `GetCursorPosition` returns the byte offset and `GetUTF8CursorPosition` returns the Unicode scalar count before the cursor.
- [x] Cursor positions past the end clamp to the end; `Insert` at the cursor preserves UTF-8 and advances both public getters consistently.
- [x] `HighlightText` with valid byte endpoints selects a range; `Insert` replaces that range (including empty-string deletion), collapses the cursor after inserted text, and clears selection for the next insertion.
- [ ] Shared clean-room policy: a negative or omitted `HighlightText` end selects through the text end; an end before the clamped start also selects from that start through the text end, without exchanging endpoints. Normalize byte endpoints before converting to scalar storage. Preserve ordered and empty ranges, UTF-8-safe `Insert`, and byte/scalar cursor getters.
- [x] ASCII cursor and selected-range editing retain their original units; renderer-facing stripped text remains synchronized with inserted text.
- [x] `Insert` derives its resulting cursor from the actual clamped edit range, including when earlier text replacement left cursor or selection indices beyond the new text.
- [x] Keyboard printable input replaces a highlighted range; Backspace and Delete remove it. Historical proof covers selection consumption and text/caret/render-cache commits before the then-existing callbacks, not the newly required presentation refresh or deferred notification. Rejected numeric input preserves the pending selection.
- [x] Historical keyboard proof established character callbacks before the then-synchronous `OnTextChanged(self, true)` and no character callback for deletion. Its timing is superseded by the unchecked lifecycle below; unselected editing and forbidden scripted-input cursor guards remain intact.
- [x] XML `letters` and `bytes` populate the existing `MaxLetters` and `MaxBytes` fields before `OnLoad` in ordinary, inherited, and runtime-template construction, including nested runtime-template EditBoxes.
- [x] Each explicit XML value, including zero, overrides the most-derived inherited value independently. Preserve the declared integer verbatim; do not add terminator arithmetic.
- [x] Keyboard input respects positive `MaxLetters` (Unicode scalars) and `MaxBytes` (UTF-8 bytes) against the proposed selected-range replacement. Zero defaults are unlimited.
- [x] An overflowing input fragment is rejected entirely, preserving existing text, caret, selection and render caches. It emits no `OnChar` or `OnTextChanged`; historical accepted-input callback timing is superseded by the unchecked lifecycle below.

- [x] Positive `MaxLetters` truncates programmatic EditBox `SetText` (including the shared `SetFormattedText` path) to the configured Unicode-scalar prefix without splitting UTF-8. Non-EditBox text and unlimited values retain their existing behavior.
- [x] Derive render text, clamp cursor/selection, and decide text callbacks from the final limited value. Different inputs that normalize to the same stored text retain the existing no-op lifecycle.
- [x] A changed EditBox `SetText` (including `SetFormattedText`) commits text, then clamps stored scalar cursor and selection endpoints to its length before callbacks; an already in-bounds cursor stays in place. Clipping is a simulator model invariant, not a native precedence claim.
- [ ] All accepted text-edit paths defer `OnTextChanged`: changed `SetText`/`SetFormattedText`, keyboard insertion/deletion, and Lua `Insert`, including selected-range deletion. Logical edits commit synchronously; a dirty flush performs actual text presentation and cursor refresh before notifying through normal scripts/hooks. Updating caches alone, immediate text-change dispatch, or forcing cursor layout inside text/cursor setters does not satisfy this boundary; the explicit pre-key dirty flush is a separate processing boundary.
- [ ] Changed `SetText`/`SetFormattedText` runs `OnTextSet(self)` synchronously. Keyboard insertion and nonempty Lua `Insert` run `OnChar` synchronously; preserve the existing keyboard payload convention of one callback per Unicode scalar. Deletion alone emits no `OnChar`.
- [ ] Absent handler edits, deliver one `OnTextChanged` per dirty flush, not per edit and not necessarily on the strictly next tick. Key-down flushes pending dirty work before handling the next key.
- [ ] Track pending origin by edit semantics: keyboard insertion sets true; changed `SetText`/`SetFormattedText` sets false; same-value `SetText` leaves it unchanged; nonempty Lua `Insert` sets true; scripted deletion alone preserves it. Retain existing keyboard deletion origin=true. This is not a generic last-API-wins rule; notification uses the accumulated pending bit, so mixed edits need not report the origin of the first edit.
- [ ] Synchronous callbacks and deferred notification observe committed logical text and coherent byte/scalar cursor getters. Handler errors reach the existing error handler without preventing later bindings or the deferred text-change phase.
- [x] Same-value EditBox text assignment is a simulator no-op: it does not dispatch this lifecycle, so a callback assigning its current text cannot recurse. It emits no `OnChar`.
- [x] Shortening text leaves subsequent `Insert` and Left/Backspace edits within bounds; non-EditBox text setters retain their existing text behavior.

The new endpoint policy is a shared simulator contract, including Wrath and Retail, not native-client parity. It is derived from the user-supplied functional examples without consulting reconstructed implementations; source5dfa94330 reproduces three endpoint-policy failures. Saved source `3fa90ab7b` Retail execution passes four unique tests, exit0; all assertions were reached. Wrath was not executed, so the shared criterion remains open. Empty highlights retain the existing cursor for subsequent `Insert`; they do not move it to the range start.

Length overflow rejection is the user-selected simulator policy, not a native-client claim. No-edit callback suppression follows the existing numeric-input rejection policy; tests establish simulator consistency, not native callback equivalence.

The genuine scrolling consumer requires cursor refresh/notification before its deferred text-change callback.
