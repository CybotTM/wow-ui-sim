# Wrath spellbook slot presentation

`FrameXML/FrameXML.toc` selects `SpellBookFrame.lua`. Its button update queries `GetSpellTexture(slot, bookType)` at line 447 and `GetSpellName(slot, bookType)` at line 495.

For Wrath only, these functions read the explicitly supplied per-book slot records from `A_Admin.SetWrathSpellBookSlot`. Numeric slots are one-based, from 1 through 1024. An unresolved slot returns one nil for texture and two nils for name; an empty supplied icon returns nil. Invalid numeric slot or non-string book inputs error. A case-insensitive `pet` selects the pet book; other strings select the player book. Names, subtext and icon filenames come from the supplied record. An empty rank is a scenario default; whether native rankless records return nil or an empty string is unknown.

The original button selection update calls `IsSelectedSpell(slot, bookType)` at `SpellBookFrame.lua:409`. Historical patch source `data/patch-api/source-cache/legacy-2026-10-09/2.3.0-wikitext.txt:34` lists `IsSelectedSpell(slot)`, and `4.0.1-wikitext.txt:68` lists its removal. The aso 3.3.5a comparison (`SpellBookFrame_Scripts.cpp:426–443`, `SpellBookFrame.cpp:1511–1545`) returns 1 for an eligible open trade-skill line or matching nonzero aura-36 form, and nil otherwise. The scenario supplies the eligible line and form per record, plus the current line and form. Unset inputs produce nil as a scenario default. Targeting and pending casts do not select a spell. The numeric-slot parser selects the pet book case-insensitively for `pet`, and the player book for any other string.

The aso 3.3.5a comparison (`SpellBookFrame.cpp:1230–1275, 1350–1431, 1436–1470`) also accepts names. The supplied records are searched case-insensitively across both books. With a second string it is treated as subtext, not a book; without one, the whole name is tried before splitting the last parenthesized suffix into name and rank. An unresolved name returns zero values. Invalid arguments produce `<function>(): Invalid spell slot`.

The supplied model has no progression-rank or spell-level ordering. When several supplied records match, the highest slot wins, with book name breaking ties; this is a scenario default, not native cache-head ordering. Unit-token second arguments are not distinguished from subtext. Unicode matching uses lowercase conversion rather than the native UTF-8 hash. These are explicit comparison gaps.

The slot interpretation and return boundaries are based on the aso 3.3.5a comparison, not a Wrath Classic runtime capture. This does not model spell learning, tab membership, pet book population, tooltip behavior or native rank defaults. Other profiles retain their existing globals.
